# Lecture deck: "Attention Is All You Need" (Vaswani et al., 2017)

An M.Sc seminar talk (statistics & data science audience) built as **one self-contained offline HTML deck**: `dist/lecture.html`, 36 numbered slides plus a References backup. The audience includes an instructor who tests the presenter's understanding, so **content accuracy matters more than anything**.

## Sources of truth
- `docs/lecture-content.md`: **content**. What is on every slide, every number, the deep dives, the settled accuracy decisions. Authoritative.
- `docs/design.md`: **design**. Palette, typography, layout, the "no bullets" pattern, motion.
- `docs/framework.md`: **engine**. Slide API, builds, components, build pipeline, review harness, gotchas.
- `paper/attention_is_all_you_need.pdf`: the paper. Figure 1 (page 3) is the reference for the SVG architecture map.

**Rules:**
- Never change, add or reorder content or numbers without the user's OK. Propose instead.
- When a change is approved, update `docs/lecture-content.md` (and `docs/design.md` / `docs/framework.md` if relevant) in the same round, so the docs always describe the final state.
- When the user asks a conceptual question or says "let's discuss", answer or give options with a recommendation, and don't edit.
- Before redesigning a slide, copy it to `src/slides/_backup/` (gitignored) and delete the copy when the user approves the new version.

## Commands
- `npm install`: dependencies + Playwright's headless Chromium.
- `npm run build`: `build/build.js` → `dist/lecture.html` (inlines CSS, JS, data, base64 fonts; pre-renders KaTeX).
- `npm run review` (optionally `-- <label>` / `-- --firefox`): build + `test/review.mjs` → screenshots of every slide × build × widget state in `review/<label>/` (default `review/latest/`) + `report.txt`. Runs Chromium offline (fails on any network request or console error) and checks:
  - build reversibility, click isolation, widget reset on re-entry,
  - footer navigation (incl. Questions), Q&A tiles + back button + Esc,
  - text ≥ 20 px, no wrapped titles, no slide IDs in slide text, reduced motion.
- `npm run gifs` (optionally `-- <names>`): build + `scripts/make-gifs.mjs` → README media in `assets/media/` (GIFs, `title.png`, `overview.png`, `overview-live.gif`). Pacing constants and the list of GIFs are at the top of the script.
- `node build/sync-fonts.js`: one-off, copies the font woff2 files into `assets/fonts/`.

**Working with the review:** it takes a few minutes, so run it in the background and look at the screenshots of the slides you touched as they appear. The automatic checks don't cover layout (overlaps, crowding, alignment), so look at the screenshots too. Never run two reviews with the same label at once. For quick iteration, build and screenshot only the touched slides; run the full review in bigger chunks. One-off screenshot scripts go in `test/_*.mjs` (Playwright must resolve from the project) and are deleted afterwards.

## Slide module API (`Deck.slide({...})`)
`id, part, title (html), cite, builds, thumb: [map ids], numbered, noFooter, hideProgress, cls, render() → html, mount(el) → { update(build), leave({to, dir, instant}) }`. Details and a complete example: `docs/framework.md`.
- `render()` runs on **every entry** (widgets reset). `update(b)` must derive all build state from `b` alone (reversibility is tested by comparing the DOM going forward vs backward).
- `data-build="k"` = visible from build k; `data-build-max="k"` = hidden after build k; both = a range.
- Clicks on `[data-interactive]`, buttons, inputs and the footer never advance the deck. Toggle `data-interactive` on only while an interaction is live.
- Math: `` tex`...` `` / `` texd`...` `` in JS, replaced by KaTeX HTML at build time. **No `${}` inside tex``** (the build fails). For per-value labels, pre-render each variant.
- Slides are authored in canvas px (1920×1080). `C.ov(x, y, html, anchor)` overlays HTML (e.g. KaTeX) on SVG coordinates. `Deck.stageRect(el)` = an element's box in canvas px (for arrows between measured elements).
- `Deck.flip(src, dst, ms, { tail })`: FLIP a clone between two boxes (roadmap → footer, S11 map → S12 thumbnail). `Deck.jump(id)`: Questions-tile jump (final build + "← back to Questions", Esc returns).

## Deck conventions (agreed with the presenter)
- **Slide references:** the presenter uses **deck numbers** ("S7" = footer number, title = S1). Deck number = manifest index + 1 (S4 = s-tok, S8 = s-6, S12 = s-2-1a, S13 = s-2-1b, S19 = s-2-7, S21 = s-2-10, S22 = s-2-11, S24 = s-3-1, S28 = s-3-5, S33 = s-4-4). In reports write both: "8 (s-6)". Confirm when ambiguous.
- `DATA.deck.totalSlides` = number of numbered slides (36). The References slide is unnumbered.
- **Text-light:** short anchors only. On diagram slides use the **"no bullets" pattern** (build 0 = start, then titled stages `.stage-title` + `.stage-sub`, a framing line and/or a bottom line; content moves into stage titles and captions, never lost). **No semicolons** on slides. **Titles fit on one line** (the engine shrinks 54 → 46 px; shorten the title if still too long). No orphan words.
- **No "illustrative" tags, no explanatory captions on visuals, no "adapted from …" credits** on slides.
- Bold key terms use `--key` (#4F64AE). Q/K/V words keep their role colours (`b.q-ink` etc.).
- **Role colours:** source blue, target orange, Q purple, K teal, V green, problem red, attention weights = indigo ramp, non-attention heatmaps (PE) = neutral `C.rampInk`. No green "success" ticks (ink tick on a light badge).
- **Digits** come from KaTeX_Main via the digits-only "Deck Digits" face (automatic in running text). `.num` / `tspan.num` for SVG text. →, ≈, ≤ in running text: `C.sym('…')` (never on KaTeX output).
- **Every displayed distribution sums to exactly 1.00** (`C.roundDist`, largest remainder). Exact values stay in `/data`.
- **Full-flow rule:** attention walkthroughs end with the residual update (x ← x + update, then LayerNorm), not at the attention output.
- Every matrix at an arrow's head is that operation's **output**. Parameters (e.g. W^O) are shown as separate definitions.
- Titles centred, bullets left-aligned. Map thumbnail top-right on Part 2 slides (`thumb: [...]`).
- Highlights must point visibly at their evidence. Labels are centred on what they describe.
- Notation: score e, weight α, exp(·); i, j index tokens (S14 indexes vector entries by r).

## Gotchas learned
- Reversibility false positives: toggling classes can leave `class=""`, re-ordered class lists or empty `style=""`. Normalise in the test or use `el.hidden` / full `style.cssText`.
- Fonts are loaded explicitly before `init` (`FONTS` in deck.js), otherwise title fitting and measurement are wrong.
- Elements in later builds are `visibility:hidden`, not `display:none`, so measuring in `mount()` works.
- Hidden footer progress (`.progress.hidden`) must not be clickable (`pointer-events:none`).
- Mouse-clicked controls are blurred on pointerup so Space / arrows keep driving the deck.
- An SVG cropped via `viewBox` needs `overflow:hidden` to actually clip.
- Prefix slide-specific CSS classes (`.s35-…`): generic names (`.stat b`, `.gen-dim`) have clashed with styles on other slides.
- Shell heredocs: quote the delimiter (`<<'EOF'`) when the text contains backticks.
